# 0016. Dispose of the template's two new records

Status: Accepted
Date: 2026-09-24

## Context

The template moved seven commits past the pin this deployment carried, and the
family refuses ratcheting, so the wave lands complete or not at all. The
inherited folder gains the template's records 0025 and 0026. The first names a
refused saved copy on the page instead of in the console. The second is the
template's own disposition of the thirty-two records the style gained, and it is
the road by which the style's current law reaches this deployment; the style's
records themselves sit one link further up, inside the template's inherited
folder. One of those rules says a re-alignment writes a record of the child's
own naming every record the inherited folder gained, with what each bound in the
tree and what changed. This is that record.

The template's reshape of sixteen functions within the new shape limits landed
in the commit before this one, carried whole, and the template's removal of the
dead date picker styles had already landed here. The reasoning of every rule
lives in its own record, once, and is not repeated here.

## Evidence

On the final tree the docs audit agreed with its conventions, printing the
ledger's review row as advice and naming the spelling advisory as not run,
because codespell is not installed on this machine and the workflow installs it.
The selftest reported every rule firing. The lint, the type check, and the build
passed, and the 133 tests passed under the seeds 1, 42, 1234, 987654, and
20260922.

A production build served locally, with `os_content_books` holding `{not json`,
named that key in the notice with the parser's reason while the books shelf
showed the published record, and with storage cleared it showed nothing. The
loopback guard refused a probe's request to a host that does not exist by name,
and without the guard the request reached the resolver and failed with
`getaddrinfo ENOTFOUND example.invalid`.

The style's template-copy check found five records in this deployment's
decisions folder whose bodies equal the template's own. This deployment's 0001
through 0004 are the template's records of the same numbers, and its 0014 is
the template's 0023.

## Options considered

- Keep the five copies and let the check fail. Refused, since the check gates
  and the style's record behind it names deletion as the remedy, the inherited
  folder carrying each record whole and history keeping the copies.
- Edit the copies until they no longer match. Refused, because a record is
  immutable, and an edit made to pass the check would hide a copy rather than
  remove it.
- Leave the spelling gap unreported, as decision 0015 left the template's lint
  waiver unreported because the template had already sent it upstream. Refused,
  because this deployment's own record brings a real word the template's entry
  does not cover, and a dismissal repeated in every commit message is a
  workaround this deployment makes itself.

## Decision

The template's changes to the shared source, the suites, and the tool
configuration are carried whole, as decision 0006 requires, and the loader suite
keeps its adaptation to the real record. The rulebook, the docs audit, and its
new selftest are recopied and re-pinned in CI, and the inherited folder is
carried whole at the new pin. The guide, the map, and the baseline are
re-adapted from the template's diff, and the content model, theming, and
roadmap documents are taken as the template wrote them, with each citation
pointed at the inherited copy it names. The five copies are deleted, and the
living documents that cited them now cite the inherited folder. The upstream
file moves its pin and carries one entry, the spelling ignore list this
deployment cannot reach.

## Consequences

This deployment and the template are the same application again, on the
style's current law. The decisions folder holds only this deployment's own
choices, from 0005 on, and a citation of a template record now reads the pinned
inherited copy rather than the template's moving main branch. The upstream file
holds one entry until the template rules on it.

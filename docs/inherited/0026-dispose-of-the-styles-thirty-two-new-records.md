# 0026. Dispose of the style's thirty-two new records

Status: Accepted
Date: 2026-09-24

## Context

The style moved fifty-two commits past the pin this project carried, and the family
refuses ratcheting, so the wave lands complete or not at all. The template gained
thirty-two decision records, 0051 through 0082, and one of them rules that a
re-alignment writes a record of the child's own naming every record the inherited
folder gained, with what each bound in the tree and what changed, because reading a
record is not applying it. This is that record. The reasoning of each rule lives in its
own record, once, and is not repeated here.

The re-alignment first ran against the template's commit a0db0a4 and was held there,
because the new selftest could not pass in this tree and two other carried bytes broke
the style's own law. The three defects went upstream, the style answered them, and the
re-alignment lands at 66ba9f5, which carries every fix. Two changes ahead of this one
made the tree ready for the new law. Sixteen functions were reshaped within the shape
limits, and the console lines of the record's door became a notice on the page under
[decision 0025, Name a refused saved copy on the page](0025-name-a-refused-saved-copy-on-the-page.md).

## Evidence

On the final tree the docs audit agreed with its conventions, printing two advisories,
the ledger's review row and a list colon in decision 0025, and naming the spelling
advisory as not run because codespell is not installed on this machine; the workflow
installs it. The selftest reported every rule firing. The lint, the type check, and the
build passed, and the 134 tests passed under the seeds 1, 42, 1234, 987654, and 20260922.

The reshape ahead of this change was held to the built site, where 84 states across
every route, each in-page button, and each library entry's detail hashed the same
before and after. The loopback guard was proved by a probe that fetched a host that
does not exist. With the guard the suite refused it by name, and without it the request
reached the resolver and failed with `getaddrinfo ENOTFOUND example.invalid`.

## Options considered

- Carry the law and skip the dispositions, since most of the rules bind through checks.
  Refused by the rule itself, and rightly, because several of the thirty-two bind only
  through review, and a rule with no check reaches the tree only through a hand that
  says what it did with it.
- Write one record per gained rule. Refused, because the rules arrived as one wave and a
  reader wants one place that says what the wave did here.
- Land at a0db0a4 with a patched copy of the selftest. Refused by the owner, who held the
  re-alignment until the style fixed its own bytes.

## Decision

Recopy the rulebook, the docs audit, its new selftest, and the inherited folder whole,
re-pin all three scripts and the rulebook in CI, carry the tool configuration's new
blocks, re-adapt the guide, the map, the baseline, and the README from the template's
diff, open the invariants ledger, and move the pin. The six entries the upstream file
held are deleted, as the style's ruling on them directs. The two security waivers stand in
the narrow, reason-bearing form the template already prescribed, the home for a dismissed
advisory is now the commit message, and the three defects the held work reported are fixed
in the template, whose bytes this project takes for the console comment and the baseline
sentence. Each gained record is disposed of below.
